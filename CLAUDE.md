# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Obzorarr is a SvelteKit 2 / Svelte 5 "Wrapped for Plex" app running on Bun with SQLite (Drizzle ORM). It is deployed as a single Bun server via `svelte-adapter-bun`.

## Essential Commands

Run everything from the repository root. Bun is the only package manager (`bun.lock`, `bunfig.toml`).

| Command | Purpose |
| --- | --- |
| `bun install` | Install deps; `postinstall` runs `prek install`, `prepare` runs `svelte-kit sync` |
| `bun run dev` | Dev server. **Does not load `.env`** — configure Plex through onboarding/admin UI |
| `bun run dev:env` | Dev server with `--env-file=.env`; use only to exercise env-precedence/"Locked by environment variable" UI |
| `bun run check` | `svelte-kit sync && svelte-check` — the type-check gate (CI + pre-push) |
| `bun run test` | Full suite: `bun test --env-file=.env.test` |
| `bun run check:biome` | Biome lint + format check (`biome check .`) |
| `bun run lint:fix` / `bun run format` | Autofix lint / write formatting |
| `bun run build` | Production build into `build/` |
| `bun run db:generate` | Generate a new migration in `drizzle/` from `schema.ts` |
| `bun run db:migrate` | Apply migrations via `scripts/migrate.ts` (standalone; the app also auto-migrates on boot) |

Targeted test runs (Bun's runner; `bunfig.toml` sets `root = "./tests"` and preloads `tests/setup.ts`):

```bash
bun test --env-file=.env.test tests/unit/sharing/service.test.ts   # one file
bun test --env-file=.env.test -t "rejects stale settingsVersion"   # one case by name
```

`bunfig.toml` enables coverage with `line = 0.8, function = 0.8` thresholds, so a full `bun run test` fails when coverage regresses below 80%.

`svelte-check` and `bun test` resolve `$lib/*` through `.svelte-kit/tsconfig.json`. If imports suddenly fail to resolve, run `bunx svelte-kit sync`.

## Architecture Overview

**Request pipeline.** `src/hooks.server.ts` composes the entire cross-cutting stack with `sequence(...)`, and the order is load-bearing:

```
requestFilterHandle → rateLimitHandle → proxyHandle → csrfHandle →
initializationHandle → securityHeadersHandle → authHandle → onboardingHandle → authorizationHandle
```

`proxyHandle` runs before everything that reads `event.url`, because it is the only place `X-Forwarded-Host`/`X-Forwarded-Proto` may rewrite the URL (gated on `TRUST_PROXY`). Downstream code — including the HSTS decision — must read `event.url`, never the raw headers. `init` (`ServerInit`) points at `initializeServer` in `src/lib/server/startup.ts`, which reconciles env-vs-DB settings and interrupted syncs before the first request.

**Layers.**
- `src/lib/server/**` — server-only domain modules (`auth`, `plex`, `sync`, `stats`, `sharing`, `slides`, `admin`, `security`, `funfacts`, `logging`, `anonymization`). SvelteKit enforces that these never reach the client bundle.
- `src/lib/**` (non-`server`) — shared types/schemas, client helpers, Svelte components. Zod schemas that both sides need live here (e.g. `src/lib/stats/types.ts`, `src/lib/slides/types.ts`), and the server re-exports them (`src/lib/server/slides/types.ts` does `export * from '$lib/slides/types'`).
- `src/routes/**` — thin: load functions and form actions that delegate to `$lib/server/*` services. Business logic does not live in route files.

**Stats pipeline.** `play_history` rows (synced from Plex) → pure calculators in `src/lib/server/stats/calculators/` → assembled by `src/lib/server/stats/engine.ts` → serialized as JSON into the `cached_stats` table. Reads go back through `parseUserStats` / `parseServerStats` in `stats/serialization.ts`, which validate against `UserStatsSchema` / `ServerStatsSchema`. Because cached rows are schema-validated on read, any change to those schemas must be paired with `invalidateCache()` handling or existing cache rows will throw `StatsParseError`.

**Database.** One shared singleton in `src/lib/server/db/client.ts`. It sets the WAL/foreign-key/busy-timeout pragmas, refuses to open a non-test path when `NODE_ENV=test`, and runs `migrate(db, { migrationsFolder: './drizzle' })` on import for file-backed databases. Always import `db` (and `sqlite`) from there; never construct another `Database` in application code.

**Settings authority.** `src/lib/server/admin/settings.service.ts` is the single source of truth for `app_settings`. Environment variables outrank DB rows: `clearConflictingDbSettings()` at startup drops DB rows that an env var now controls. Never read `process.env` for a user-configurable setting inside a route — go through the service.

## Common Change Workflows

**Change the database schema**

1. Edit `src/lib/server/db/schema.ts`.
2. Run `bun run db:generate` and commit both the new `drizzle/NNNN_*.sql` and the updated `drizzle/meta/` snapshot.
3. Mirror the change in the `CREATE TABLE` block in `tests/setup.ts` — that file builds the in-memory test schema by hand, so tests silently diverge from production otherwise (see the `share_settings_user_year_unq` comment there for a real instance of this).
4. Add new tables to `sharedTestDbTables` / `resetSharedTestDb()` in `tests/helpers/db.ts`.
5. Do not wrap migration SQL in `BEGIN`/`COMMIT`; drizzle's bun-sqlite migrator already runs each file in one transaction.

**Add a Wrapped slide**

1. Add the literal to the `SlideType` union and to `DEFAULT_SLIDE_ORDER` in `src/lib/components/slides/types.ts`, plus its props interface.
2. Add the same literal to `SlideTypeSchema` in `src/lib/slides/types.ts` (the zod enum used for validation/persistence).
3. Create `src/lib/components/slides/<Name>Slide.svelte` and export it from `src/lib/components/slides/index.ts`.
4. Add the `{:else if slide.type === '…'}` branch in `src/lib/components/wrapped/SlideRenderer.svelte`.
5. Add the human label to both display maps: `src/routes/admin/slides/+page.svelte` and `src/routes/onboarding/settings/+page.server.ts`.
6. If it needs new data: add a calculator under `src/lib/server/stats/calculators/`, export it from that directory's `index.ts`, wire it into `stats/engine.ts`, and extend the stats zod schemas in `src/lib/stats/types.ts`.

**Add or change an admin setting**

1. Add the key to `AppSettingsKey` and to the relevant `*_SETTINGS_KEYS` tuple in `settings.service.ts`, then add an atomic writer alongside the existing `set*Atomic` helpers.
2. In the route's `load`, expose `settingsVersionISO(await getAppSettingsUpdatedAt(KEYS))` as a form field.
3. In the action, run `inlineOccCheck` (payload `{ conflict: true, error: OCC_CONFLICT_MESSAGE }`) or `externalOccCheck` (payload carries `code: OCC_CONFLICT_CODE`) before writing, and wrap the action map in `requireAdminActions({...})`.
4. On the client, pass `surfaceOccConflict` to superForm's `onUpdate` (`src/lib/utils/occ-form.ts`) — without it a 409 stale write still renders a success toast.

**Add a fun-fact template**: create the array in `src/lib/server/funfacts/templates/<category>.ts` and register it inside `initializeTemplates()` in that directory's `index.ts`; also add it to `ALL_TEMPLATES` and `TEMPLATES_BY_CATEGORY`.

## Implementation Decisions

| Situation | Preferred approach | Avoid |
| --- | --- | --- |
| Guarding an admin form action | `requireAdminActions({...})` wrapper from `$lib/server/auth/guards` | Ad-hoc `if (!locals.user?.isAdmin)` per action |
| Guarding an authenticated (non-admin) action | `requireUserActions({...})` — actions bypass the route `load`, so an unauthenticated POST reaches the handler | Relying on the route's redirecting `load` |
| Guarding an admin *page* | `isAdminRouteId` in `authorizationHandle` already 303s; `requireAdmin(locals)` in the load is defense in depth | Duplicating redirect logic in the route |
| Validating a form payload | `superValidate` + `zod4` adapter (sveltekit-superforms), schemas built with the helpers in `src/lib/server/admin/zod-helpers.ts` | Manual `FormData` parsing |
| Deciding who may view a Wrapped | `checkWrappedAccess` / `checkTokenAccess` / `checkServerWrappedAccess` in `src/lib/server/sharing/access-control.ts` | Comparing `locals.user.id` to the target id inline |
| Test that needs the real DB/services | Shared singleton `db` with `DATABASE_PATH=:memory:` (from `tests/setup.ts`) | A second `new Database(...)`, except in pure/property tests that say so |
| Reporting a domain failure from a slide action | Throw `SlideError(msg, code)` and convert with `slideErrorToFail` | Returning raw drizzle/SQLite errors to the client |

## Repository Conventions

- **Formatting** is Biome with tabs, single quotes, no trailing commas, 100-column width. `biome.json` disables several rules for `**/*.svelte` (unused vars/imports, `useImportType`, `useConst`) because the Svelte compiler handles them.
- **Commits** follow Conventional Commits, enforced by a `commit-msg` hook (`conventional-pre-commit`). `prek.toml` also configures `no-commit-to-branch --branch main`, so direct commits to `main` are blocked once hooks are installed.
- **Logging** goes through `logger` from `$lib/server/logging` with the `(message, source, metadata?)` shape, e.g. `logger.error('...', 'Startup', metadata)`. Messages and metadata are scrubbed by `logging/redactor.ts`; never bypass the logger for anything that could carry a Plex token.
- **Error surfacing to clients**: `handleError` in `hooks.server.ts` demotes 404s to info and other 4xx to warn, and returns generic messages. Form actions bypass `handleError`, so they must sanitize themselves (`slideErrorToFail`, `sanitizeApiError` / `sanitizeConnectionError` in `$lib/server/security`).
- **Route params**: the `[year=year]` matcher lives in `src/params/year.ts` and only accepts four digits.

## Testing and Validation

- Layers: `tests/unit/` (mirrors domain folders — `auth/`, `admin/`, `sharing/`, `security/`), `tests/property/` (fast-check), `tests/integration/`, `tests/helpers/`. `tests/unit/test-architecture.test.ts` asserts there is no `tests/unit/server/` directory and that no test imports Vitest or Jest APIs — Bun's runner only.
- `tests/setup.ts` is the mandatory preload: it pins `DATABASE_PATH=:memory:`, mocks `$env/dynamic/private`, `$env/static/private`, `$app/environment` (`dev: false`), and `$lib/services/toast`, then creates the schema. Because module mocks must be installed before the subject loads, subject harnesses call `mock.module(...)` first and then `await import(...)` dynamically.
- Read `tests/helpers/README.md` before adding a helper — it defines the three helper tiers (pure factories / DB helpers / subject harnesses) and the mocking order.
- Local validation order matches CI: `bun run check:biome` → `bun run check` → `bun run test`. CI (`.github/workflows/code-quality.yml`) additionally runs `bun run build` and `bun run smoke:production` against a disposable `DATABASE_PATH`.

## Critical Gotchas

- **Never point a test or QA script at a real database.** `db/client.ts` throws when `NODE_ENV=test` and the path is neither `:memory:` nor contains `test`. `bun run qa:wrapped-lookup` likewise refuses paths that already exist, are relative, sit outside a temp/test directory, or look production-like — give it a fresh absolute path under the system temp directory.
- **Do not "unify" the SSE denial codes.** `/admin/logs/stream` and `/admin/sync/stream` are denied with a 303 by `authorizationHandle` before their own `requireAdmin` 403 can run, while `/api/sync/status/stream` returns 401 JSON. The split is deliberate and documented inline in `hooks.server.ts`.
- **Plex `accountId` is PMS-local, not a Plex.tv identity.** The owner is always local `accountId=1`. Shared-user mappings are only created by a *complete* reconciliation in `src/lib/server/plex/account-reconciliation.ts`; partial/failed observations must retain the prior mapping. Never hand-edit account IDs or backfill history to "fix" attribution — see the README's "Plex identity reconciliation" section.
- **Public Wrapped denials are uniform by design.** Unknown identifier, non-public profile, and stale identity mapping all return the same not-found response so the endpoint cannot be used to enumerate users. Do not add a more specific error message on that path.
- **OCC sentinels are duplicated across the server/client boundary.** `OCC_CONFLICT_CODE` is server-only in `occ-helpers.ts` and re-declared as a literal in `src/lib/utils/occ-form.ts`; `OCC_CONFLICT_MESSAGE` is asserted verbatim by many tests. Changing either requires updating both files and the tests in the same commit.
- **CSRF is app-owned.** `svelte.config.js` sets `csrf.trustedOrigins: ['*']` because `csrfHandle` performs configured-origin checks itself. Do not re-enable SvelteKit's built-in gate as a "fix"; adjust `src/lib/server/security/csrf-handle.ts` instead.
- **New third-party origins need a CSP entry.** The nonce-mode CSP in `svelte.config.js` is strict (`script-src: self`); an external image/font/API host must be added there or it will be blocked at runtime.
